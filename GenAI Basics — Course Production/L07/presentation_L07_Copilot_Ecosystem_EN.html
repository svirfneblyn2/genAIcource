Grounding Architecture: How Enterprise Data Reaches LLMs

The foundation model does not know your company's files in advance — the orchestrator grounds the prompt prior to inference.

1. INTERCEPT & PRE-PROCESS
User Input
User submits a prompt in Teams or Word. The orchestrator extracts application context, user identity tokens, and kicks off semantic search.
2. GRAPH & SEMANTIC INDEX
Fact Retrieval
Queries Microsoft Graph. Semantic Index retrieves vector-similar documents from SharePoint/OneDrive strictly honoring the user's ACL permissions.
3. LLM ENRICHMENT
Inference Prompt
The LLM receives an augmented metaprompt: User question + Grounded authoritative document excerpts + Output schema instructions.
4. EDP & POST-PROCESS
Enterprise Protection
Output post-processing: sensitivity label filtering, PII redaction, source citations formatting. Customer data is never used to train foundation models.

Microsoft 365 Copilot • Application Envelopes

Application Envelopes & Context Grounding Boundaries

Distinguish «Chat with Web» from «Grounded in Work Data». Each M365 application scopes available context differently.

COPILOT CHAT MODES
• Web Grounded: Public web search grounding. Cannot see company files. Ideal for external research and market analysis.
• Work Grounded: Connected to enterprise tenant. Accesses user's chats, emails, and accessible SharePoint documents.
UI Toggle Warning: In Microsoft Copilot Chat, there is a visible toggle between Web and Work. Prompting about an internal project while set to Web will produce hallucinations or external web results!
IN-APP SKILL BOUNDARIES
• Outlook: Long thread summarization, draft replies grounded in meeting history.
• Teams: Instant meeting decision recaps from transcripts, unassigned action items.
• Word: Document synthesis from disparate meeting notes and source attachments.
• Excel: Formula generation and trend analysis (requires data formatted as an official Excel Table).
• PowerPoint: Transforming Word documents into slide deck narratives.

Microsoft Learn Methodology • Prompting Standard

The 4 Prompt Ingredients for Copilot (Official Standard)

Microsoft Learn trains enterprise users to avoid vague requests and build structured four-part prompts.

[GOAL]: Draft a structured rollout brief for Customer Support regarding the new VIP Free Shipping rule. [CONTEXT]: We are releasing this feature to couriers and operators this weekend. Support agents need clear qualification criteria and exception workflows. [SOURCE]: Rely strictly on attached meeting_notes_fixture.docx and executive decisions protocol. [EXPECTATIONS]: Format: Markdown with sections (Eligibility Criteria, Edge Cases, Open Questions). Max 300 words. Include source paragraph citations.
ANATOMY OF THE 4 INGREDIENTS
1. Goal
Specific action verb: summarize, identify risks, format comparison table.
2. Context
Who will read this document and why the output is being produced.
3. Source
Explicit authoritative file, link, or meeting transcript (using / reference in chat).
4. Expectations
Strict constraints on tone, brevity, mandatory sections, and citations.

Security & Governance • Enterprise Risk

Permission Trimming: Why AI Security Relies on Data Hygiene

Copilot does not invent a new access model — it strictly inherits existing user permissions via Zero Trust.

FEATURE: ZERO TRUST ACCESS BY DEFAULT
• If an engineer lacks access to the "Executive Comp 2026" SharePoint folder, Copilot can never retrieve or cite those files.
• User requests are processed within tenant boundaries with strict encryption.
• Complete isolation between organizations and restricted department sites.
CHIEF RISK: OVERSHARING IN SHAREPOINT
• Pre-AI, a sensitive spreadsheet left open to "Everyone in Company" sat unnoticed for years.
• Copilot finds everything: Any employee asking "what are upcoming headcount changes?" surfaces the document instantly via Semantic Index.
• Copilot rollout requires rigorous pre-deployment access audits in SharePoint and Teams!
ENTERPRISE DATA PROTECTION (EDP)
• No Foundation Training: Prompts and tenant data are never used to train foundation OpenAI/Microsoft models.
• Data Residency: Customer data remains within defined geographic boundaries (EU/US).
• Purview Integration: Native support for Sensitivity Labels, customer-managed keys, and comprehensive audit logs.

Context Engineering • IDE Workspace

What Copilot Sees in Your IDE: The Context Stack

Context in the code editor is not magic — it is an engineered stack assembled prior to each prompt completion.

VS CODE CONTEXT RETRIEVAL HIERARCHY
1. Cursor & Active Buffer: Code prefix and suffix around cursor.
2. Neighbor Tabs: Other files currently open in editor tabs.
3. Repository Instructions: .github/copilot-instructions.md in project root (enforces code style and constraints).
4. Workspace Index: Local embedding vector index of classes and methods.
5. Configured MCP Tools: External databases, APIs, and CLI runners.
SAMPLE .github/copilot-instructions.md: - Always use explicit Python type annotations. - Any modification to pricing logic requires unit tests in pytest. - Preserve existing public API contracts and method signatures. - Never hardcode fee thresholds or keys; read from config objects. - Summarize proposed plan before applying code modifications.

Windows Copilot vs Copilot+ PC: Cloud vs On-Device NPU

Distinguish the web application assistant from on-device AI capabilities accelerated by local NPU hardware.

CLOUD COPILOT APP ON WINDOWS
• Standard web/desktop Progressive Web App (PWA).
• Voice interaction, screenshot reasoning, Windows settings assist.
• Requires internet connection and Microsoft / Entra account.
• Processed on remote cloud datacenter clusters.
LOCAL COPILOT+ PC FEATURES (40+ TOPS NPU)
• Recall: Local semantic photographic timeline (runs entirely on-device with pause, filter, and encryption controls).
• Click to Do: Instant context actions on on-screen text/images without sending frames to third-party clouds.
• Live Captions & Studio Effects: 0ms latency hardware audio translation and webcam video processing.
Regional & Policy Variations (EEA vs US): Depending on regulatory environments (e.g., EU DMA) and group policies, certain features (Recall, Click to Do) may be disabled or withheld. Always inspect local device capabilities before planning a workflow!

Decision Framework • Operational Evaluation

Copilot Decision Matrix: 4 Evaluation Checkpoints

A practical checklist before kicking off any task: select the right surface and enforce safety boundaries.

4 QUESTIONS OF THE OPERATING MAP
1. Where is the authoritative source of truth?
Repository (code), M365 Graph (documents/meetings), or local OS state.
2. What are the permitted assistant actions?
Advise only, draft files, execute test suites, or create branch/PR.
3. What is the mandatory human checkpoint?
Code diff inspection, running unit tests, source link fact-checking.
4. What durable evidence artifact is retained?
Pull Request, SharePoint versioned doc, CI test pass log.
When Autonomous AI is STRICTLY FORBIDDEN (Red Zone):
• Executing financial transactions or issuing customer refunds.
• Direct production deployments bypassing CI and human sign-off gates.
• Processing sensitive PII or health data on surfaces lacking verified Enterprise Data Protection.
