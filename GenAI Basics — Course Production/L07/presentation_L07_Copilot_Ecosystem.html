Архитектура Grounding: как корпоративные данные попадают в LLM

Модель не знает ваших корпоративных документов заранее — оркестратор заземляет промпт перед вызовом нейросети.

1. ПЕРЕХВАТ И ПРЕОБРАБОТКА
Пользовательский ввод
Сотрудник пишет запрос в Teams или Word. Оркестратор парсит контекст приложения, извлекает метаданные пользователя и инициирует семантический поиск.
2. GRAPH & SEMANTIC INDEX
Извлечение фактов
Обращение к Microsoft Graph. Semantic Index находит векторно близкие документы в SharePoint/OneDrive с обязательным учетом прав текущего аккаунта (ACL).
3. LLM ОБОГАЩЕНИЕ
Генерация ответа
Базовая модель получает гигантский системный промпт: Запрос пользователя + Извлеченные проверенные фрагменты документов + Инструкции формата.
4. EDP & БЕЗОПАСНОСТЬ
Enterprise Data Protection
Пост-процессинг ответа: проверка на PII/DLP, разметка ссылок на первоисточник (Citations). Никакие корпоративные данные не используются для дообучения глобальных моделей.

Контекстные оболочки в офисных приложениях

РЕЖИМЫ COPILOT CHAT

Формула промпта для Copilot: 4 обязательных ингредиента

Microsoft учит сотрудников не писать абстрактные пожелания, а собирать структурированный рабочий запрос.

[GOAL / ЦЕЛЬ]: Сформируй структурированный бриф для службы поддержки по запуску правила бесплатной VIP-доставки. [CONTEXT / КОНТЕКСТ]: Мы готовим выкатку обновления для курьеров и операторов в эти выходные. Саппорту нужно четко знать критерии активации и исключения. [SOURCE / ИСТОЧНИК]: Используй только прикрепленный файл meeting_notes_fixture.docx и протокол решений менеджмента. [EXPECTATIONS / ОЖИДАНИЯ]: Формат: маркдаун с разделами (Критерии, Пограничные случаи, Открытые вопросы). Объем до 300 слов. Добавь цитаты первоисточника.
АНАТОМИЯ ИНГРЕДИЕНТОВ
1. Goal (Цель)
Четкий глагол действия: суммаризируй, выдели риски, напиши таблицу.
2. Context (Контекст)
Кто целевая аудитория документа и зачем этот результат создается.
3. Source (Источник)
Явная ссылка на авторитетный файл, ссылку или стенограмму (символ / в чате).
4. Expectations (Ожидания)
Жесткие ограничения по стилю, длине, тону и обязательным пунктам.

Безопасность и комплаенс • Архитектурные риски

Permission Trimming: почему безопасность зависит от гигиены данных

Copilot не создает новую модель доступа — он строго наследует существующие права пользователя в организации.

ФИЧА: ZERO TRUST ПО УМОЛЧАНИЮ
• Если у инженера нет доступа к папке «Budgets 2026» в SharePoint, Copilot никогда не прочитает и не процитирует эти файлы.
• Запросы сотрудника обрабатываются изолированно внутри тенанта компании.
• Нет утечек между организациями и между департаментами с разделенными правами.
ГЛАВНЫЙ РИСК: ОВЕРШЕРИНГ (OVERSHARING)
• До эры AI документ с зарплатами или сокращениями мог лежать на общедоступном диске годами, и никто о нем не знал.
• Copilot находит всё: любой сотрудник, спросив «какие изменения планируются в штате?», моментально получит скрытый документ через Semantic Index.
• Внедрение Copilot требует предварительного аудита прав в SharePoint и Teams!
ENTERPRISE DATA PROTECTION (EDP)
• No Training: Промпты и корпоративные документы не используются для обучения базовых моделей OpenAI/Microsoft.
• Data Residency: Данные остаются внутри выбранного географического региона (EU/US).
• Purview Compliance: Поддержка меток чувствительности (Sensitivity Labels), шифрования и автоматического журналирования аудита.

Что видит Copilot в вашей IDE: стек контекста

Контекст в редакторе кода — это не магия, а строго сконструированный инженерный стек.

ИЕРАРХИЯ СБОРА КОНТЕКСТА В VS CODE
1. Курсор и активный файл: код вокруг курсора (Prefix & Suffix).
2. Открытые вкладки (Neighbor Tabs): файлы, открытые в редакторе прямо сейчас.
3. Корпоративные инструкции: файл .github/copilot-instructions.md в корне репозитория (кодирует кодстайл и правила).
4. Индекс рабочей области (Workspace Index): локальные эмбеддинги структуры проекта и классов.
5. Внешние инструменты (MCP / Extensions): подключенные базы данных и API.
ПРИМЕР .github/copilot-instructions.md: - Всегда используй строгую типизацию Python (type hints). - При изменении бизнес-логики обязательно создавай unit-тесты на pytest. - Сохраняй публичный контракт существующих классов. - Никогда не хардкодь тарифы и ключи — выноси в параметры конфига. - Перед редактированием кода кратко объясни свой план действий.

Windows Copilot и Copilot+ PC: облако vs локальный NPU

Разделяйте облачное веб-приложение ассистента и аппаратные AI-возможности новой операционной системы.

ОБЛАЧНОЕ ПРИЛОЖЕНИЕ COPILOT НА WINDOWS
• Стандартное веб/десктоп приложение (PWA).
• Поддерживает голосовой ввод, распознавание скриншотов, поиск настроек системы.
• Требует подключения к интернету и аккаунта Microsoft / Entra ID.
• Данные обрабатываются в облачном дата-центре.
ЛОКАЛЬНЫЕ ФУНКЦИИ COPILOT+ PC (NPU 40+ TOPS)
• Recall: локальный семантический снимок истории работы (полностью на устройстве, с возможностью паузы и шифрования).
• Click to Do: контекстные действия с объектами на экране без отправки скриншота в стороннее облако.
• Live Captions & Studio Effects: аппаратный перевод речи и обработка видеопотока веб-камеры с задержкой 0 мс.
Региональные различия (EEA vs US): В зависимости от законодательства (например, DMA в Евросоюзе) и корпоративных политик некоторые функции (Recall, Click to Do) могут быть заблокированы администратором или недоступны в регионе. Всегда проверяйте статус фичи на целевой машине!

Матрица выбора инструмента: 4 проверочных вопроса

Чек-лист перед стартом любой задачи: как определить правильную поверхность и избежать рисков.

4 ВОПРОСА ОПЕРАЦИОННОЙ КАРТЫ
1. Где авторитетный источник правды?
Репозиторий (код), M365 Graph (документы/письма) или локальная ОС.
2. Каковы границы действия ассистента?
Только совет, черновик файла, запуск тестов или создание PR.
3. В чем заключается чекпоинт человека?
Инспекция diff, запуск unit-тестов, факт-чекинг ссылок.
4. Какой артефакт сохраняется в качестве evidence?
Pull Request, версия документа в SharePoint, лог тестов CI.
Когда Copilot использовать ЗАПРЕЩЕНО:
• Проведение финансовых транзакций без прямого участия человека.
• Прямой деплой кода в production без прохождения CI-пайплайна.
• Обработка закрытых PII/медицинских данных на поверхностях без подтвержденного статуса Enterprise Data Protection.

СТРУКТУРА ОПЕРАЦИОННОЙ КАРТЫ (3 СТРОКИ)
Для каждой из 3 задач заполните колонки:
• Task: Конкретное действие (например, «Рефакторинг калькулятора тарифов Glovo»).
• Surface: GitHub VS Code Agent Mode / M365 Word / Copilot CLI.
• Context Source: Ветка git, файл тикета Jira, заметки созвона.
• Allowed Action: Редактирование файлов и запуск локальных тестов.
• Human Checkpoint: Проверка diff и прогон coverage > 90%.
• Evidence: Ссылка на PR с зеленым CI.
• Policy Dependency: Корпоративная политика запрета на сторонние MCP.
