## Цели

1. Выбрать задачу из своей работы, где агенту нужны данные или действия.
2. Описать 2–3 инструмента по правилам урока.
3. Проверить в Google AI Studio, какие вызовы предлагает модель.
4. Решить, где нужно подтверждение человека, какой лимит шагов и что писать в журнал.

## Шаги

### 1. Задача (15 мин)
Опишите в 3–5 предложениях, кто пользуется агентом и что он должен уметь. Примеры: поддержка клиентов (заказы, возвраты), склад (остатки, резерв), HR (отпуска, справки), ИТ-поддержка (статус заявки, сброс пароля).

### 2. Инструменты (30 мин)
Для каждой из 2–3 функций заполните:

| Поле | Пример |
|---|---|
| Имя | `get_order_status` |
| Описание: что, для чего, когда звать | «Текущий статус, курьер и время доставки ОДНОГО заказа по номеру. Звать, когда клиент спрашивает, где заказ.» |
| Параметры | `order_id` (строка, обязательный) |
| Риск | читает данные / меняет данные / тратит деньги |

Хотя бы одна функция должна что-то менять (например, `create_return`), чтобы было где поставить подтверждение.

### 3. Проверка в AI Studio (40 мин)
1. aistudio.google.com → новый чат → модель **Gemini 3.8 Flash** (бесплатно).
2. Run settings → Tools → **Function calling** → Edit → заполните ваши функции → Save.
3. Задайте 5 вопросов:
   - 3 обычных, где нужен инструмент;
   - 1, где инструмент не нужен;
   - 1 «опасный» (просьба сделать то, чего у агента быть не должно).
4. Для каждого вызова впишите в поле «function response» синтетический JSON-ответ и посмотрите финальный ответ модели.
5. Сделайте скриншот хотя бы одного полного цикла (вопрос → вызов → ответ функции → ответ модели).

### 4. Риски (20 мин)
В `risks.md` ответьте: какие функции требуют подтверждения человека; какой лимит шагов вы бы поставили; что писать в журнал; как агент должен реагировать на «опасный» вопрос.

### 5. По желанию
Соберите настоящего агента промптом со слайда 13 (Claude Code, Codex или Antigravity) с вашими функциями. Ключ Gemini API бесплатно выдаётся в AI Studio → Get API key; храните его в переменной окружения.

## Критерии оценки (10 баллов) = 4 правила со слайда 18

| Критерий | Баллы |
|---|---|
| Узкие инструменты: одна функция — одна задача, описание отвечает «что, для чего, когда» | 3 |
| Проверка: аргументы и права проверяет программа (risks.md) + таблица 5 вопросов | 3 |
| Человек подтверждает действия с последствиями | 2 |
| Лимит шагов и журнал описаны | 1 |
| Только синтетические данные | 1 |

**Частые ошибки:** одна функция «делать всё»; описание в два слова; нет вопроса без инструмента; опасный вопрос выполнен без подтверждения; настоящие данные клиентов.
