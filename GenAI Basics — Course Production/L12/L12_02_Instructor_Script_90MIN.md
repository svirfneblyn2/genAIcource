### Слайд 01 (00:00–02:00) • MCP и фреймворки агентов

**На экране:** Название урока; справа схема «MCP → серверы» (HTML).

#### Спикер (2 мин)
> Приветствие. В L11 мы вручную описали функцию get_order_status для одной модели в AI Studio. Сегодня — как сделать инструмент один раз и подключать его к любому ИИ-приложению: Claude, ChatGPT, VS Code, LM Studio. Для этого есть стандарт MCP, Model Context Protocol.

### Слайд 02 (02:00–06:00) • Без стандарта каждое ИИ-приложение подключают к каждому сервису отдельно

**На экране:** Схема «без MCP 3 × 3 = 9 связок, с MCP 3 + 3 = 6» и вывод 10 × 10 = 100 против 10 + 10 = 20.

#### Спикер (4 мин)
> В прошлом уроке функция get_order_status жила внутри одного чата AI Studio. А если её нужно дать Claude, ChatGPT, VS Code и своему боту? Без стандарта каждую пару «приложение — сервис» связывают отдельным кодом: у каждого свой формат описания инструментов, свой вход, свои ошибки.
>
> Слева три приложения и три сервиса: девять отдельных связок. Справа то же через MCP: каждый подключается один раз к общему стандарту, и связок шесть. Чем больше приложений и сервисов, тем больше выигрыш.

### Слайд 03 (06:00–11:00) • MCP — как USB-C для ИИ-приложений: один разъём для любых инструментов

**На экране:** Схема-хаб: приложения слева, MCP в центре, серверы справа; определение MCP.

#### Спикер (5 мин)
> Официальная документация сравнивает MCP с портом USB-C: как USB-C стандартно подключает устройства, так MCP стандартно подключает ИИ-приложения к внешним системам. Слева приложения: Claude, ChatGPT, VS Code, LM Studio. Справа то, к чему подключаемся: Google Drive, GitHub, Figma, ваша база данных.
>
> MCP придумала Anthropic в ноябре 2024 и сразу открыла как стандарт; его поддержали OpenAI, Google, Microsoft. Важно: MCP не заменяет вызов функций из L11. Внутри тот же механизм: модель предлагает вызов, программа выполняет. MCP стандартизирует, как программа узнаёт об инструментах и как их вызывает.

### Слайд 04 (11:00–16:00) • Три роли: приложение-хост, клиент внутри него и сервер с инструментами

**На экране:** Три карточки хост → клиент → сервер и три вида того, что даёт сервер.

#### Спикер (5 мин)
> Три роли. Хост — приложение, в котором вы общаетесь с ИИ: Claude, ChatGPT, VS Code. Сервер — отдельная программа, которая даёт инструменты и данные: сервер Google Drive умеет искать и читать файлы, сервер GitHub — задачи и код. Клиент — маленький «разъём» внутри хоста, по одному на каждый подключённый сервер; пользователь его не видит.
>
> Сервер может давать три вида вещей. Инструменты — действия, как наша get_order_status. Ресурсы — данные для чтения: файлы, записи в базе. Промпты — готовые шаблоны, например «сделай сводку по задаче». Чаще всего вы встретите инструменты.

**На экране:** Скриншот меню коннекторов Claude с выносками 1–3.

### Слайд 06 (21:00–26:00) • Перед вызовом инструмента Claude спрашивает разрешение и показывает, что отправит

**На экране:** Скриншот запроса разрешения Claude для инструмента Figma с выносками 1–3.

#### Спикер (5 мин)
> Это правило «человек в цикле» из L11 в настоящем продукте. Мы попросили Claude нарисовать схему обработки жалобы, и он решил вызвать инструмент Generate Diagram из сервера Figma. Прежде чем вызвать, Claude показывает: какой инструмент, из какого сервера и что именно он отправит — здесь код схемы с текстом про жалобу.
>
> Три кнопки. Decline — отказать. Allow once — разрешить один раз. Always allow — больше не спрашивать для этого инструмента. Правило: «всегда» только для безопасных инструментов, которые читают. Всё, что отправляет письма, удаляет, платит или публикует, подтверждаем каждый раз и читаем, что уходит.

**На экране:** Скриншот «Плагинов» ChatGPT с выносками 1–3, крупный фрагмент пункта 2, предупреждение о платном плане, другие хосты.

Добавить свой сервер можно только на платных тарифах (режим разработчика); в документации OpenAI бесплатный план среди допущенных не указан.

### Слайд 08 (30:00–34:00) • Официальный реестр: десятки тысяч серверов, и опубликовать может любой

**На экране:** Крупный фрагмент официального реестра MCP (заголовок и две карточки) и число ≈ 44 000.

#### Спикер (4 мин)
> Где искать серверы. Официальный реестр registry.modelcontextprotocol.io — пока в статусе превью. Мы посчитали через его API около 44 тысяч записей. Посмотрите на «недавно обновлённые»: от чатов для агентов до данных о криптовалютах. Реестр хранит только описания и не проверяет, безопасен ли сервер.
>
> Правило: для популярного сервиса ищите сервер от самой компании. GitHub, Notion, Figma, Atlassian, Stripe и Slack запускают официальные серверы; например, GitHub держит свой по адресу api.githubcopilot.com/mcp, а старый пакет из репозитория примеров устарел. Сторонний сервер для почты или банка — красный флаг.

### Слайд 09 (34:00–39:00) • Та же функция из L11 становится MCP-сервером за 10 строк

**На экране:** Справочный код мини-сервера MCP на Python (MCPServer, @mcp.tool()).

#### Спикер (5 мин)
> Для тех, кто программирует. Официальный Python-пакет mcp (версия 2, Python 3.11+) содержит класс MCPServer — самый короткий способ сделать сервер; в старых статьях он называется FastMCP. Создаём сервер с именем courier, ставим над функцией строку @mcp.tool() — и функция get_order_status из L11 становится инструментом MCP. Docstring снова служит описанием для модели. mcp.run() запускает сервер на этом компьютере.
>
> Главное отличие от L11: там функция жила внутри одного приложения. Здесь она — отдельный сервер, который можно подключить к любому хосту, поддерживающему MCP. Проверено с mcp 2.3.0, 16.10.2026; перед показом установите пакет (pip install mcp) и проверьте ещё раз.

### Слайд 10 (39:00–43:00) • Подключение — это несколько строк настроек: где лежит сервер и как его запустить

**На экране:** Файл настроек mcpServers и три понятия: локальный, удалённый сервер, MCP Inspector.

#### Спикер (4 мин)
> Чтобы хост узнал о сервере, ему дают несколько строк настроек. Для локального сервера: имя, команда запуска и аргументы — хост сам запускает программу на вашем компьютере. Такой формат с разделом mcpServers используют Claude Desktop (файл claude_desktop_config.json), LM Studio и Cursor (файл mcp.json); у VS Code похожий, но раздел называется servers. Путь к файлу сервера указывайте полный. Укажите полный путь к python.exe, где установлен пакет mcp, например C:\courier\.venv\Scripts\python.exe: просто «python» хост может не найти.
>
> Удалённые серверы живут в интернете: вы указываете адрес и входите своим аккаунтом, как при подключении Google Drive в Claude. Перед подключением свой сервер удобно проверить в MCP Inspector — это официальная утилита, которая показывает список инструментов сервера и позволяет вызвать их вручную.

### Слайд 12 (47:00–52:00) • Подключённый сервер получает доступ к вашим данным. Подключайте только проверенные

**На экране:** Четыре риска MCP и нумерованный список правил.

#### Спикер (5 мин)
> MCP-сервер — это программа, которой вы даёте доступ к почте, файлам, задачам. Четыре типичных риска. Отравленное описание: в описании инструмента, которое модель читает, спрятана команда; пользователь её не видит, а модель может послушаться. Чужой текст в данных: тот же prompt injection из L11, но через письма и страницы, которые читает сервер. Лишние права: сервер просит больше, чем нужно. Подмена: сервер был безопасным, а после обновления стал делать другое.
>
> Правила простые: подключать серверы от известных авторов или своей компании, давать минимум прав, выключать ненужные, читать запрос разрешения и разрешать «всегда» только чтение. Для рабочих данных — только коннекторы, одобренные вашей компанией.

### Слайд 13 (52:00–56:00) • Вызов функций, MCP и фреймворк: слои вложены друг в друга, их не надо путать

**На экране:** Вложенные слои: фреймворк агентов ⊃ MCP ⊃ вызов функций.

#### Спикер (4 мин)
> Три слова часто путают. Вызов функций (L11) отвечает на вопрос, как модель просит действие. MCP отвечает, как приложение находит готовые инструменты и вызывает их стандартным способом. Фреймворк агентов отвечает, кто крутит цикл: сколько шагов, что запомнить, где спросить человека, как записать журнал.
>
> Слои складываются: фреймворк может использовать MCP-серверы, а внутри всё равно работает вызов функций. Но не начинайте с «MCP плюс фреймворк» для задачи, где хватит одного чата с двумя функциями.

### Слайд 14 (56:00–60:00) • За два года MCP стал общим стандартом, а не проектом одной компании

**На экране:** Три числа (загрузки SDK, число серверов, передача в Linux Foundation) и шкала времени 2024–2026.

#### Спикер (4 мин)
> Почему MCP стоит учить. По официальному блогу MCP, SDK скачивают почти полмиллиарда раз в месяц. Уже в декабре 2025 было больше 10 тысяч активных публичных серверов. В том же декабре Anthropic передала MCP в Agentic AI Foundation при Linux Foundation, её соучредители — Anthropic, Block и OpenAI. То есть стандарт больше не принадлежит одной компании.
>
> Минус быстрого роста: стандарт меняется. Спецификация от 28 июля 2026 стала проще для облачных серверов; часть старых функций устарела. Python-библиотека перешла на версию 2, и код из статей 2025 года может не запускаться.

### Слайд 16 (65:00–70:00) • Фреймворки агентов: готовый цикл, память, подтверждения и журнал

**На экране:** Список фреймворков агентов с лицензиями и назначением; справа три слоя: ваш агент / фреймворк / модель + MCP-серверы.

#### Спикер (5 мин)
> Фреймворк агентов — библиотека, которая берёт на себя цикл из L11 и всё вокруг него: память между шагами, передачу задачи другому агенту, паузы на подтверждение человеком, журнал (трассировку). OpenAI Agents SDK и Claude Agent SDK — от поставщиков моделей; Claude Agent SDK использует тот же движок, что Claude Code, код Python-версии открыт под MIT, но использование SDK регулируется коммерческими условиями Anthropic.
>
> Google ADK — агенты на Gemini и других моделях с удобным деплоем в Google Cloud. LangGraph описывает агента как схему шагов с памятью и паузами. Microsoft Agent Framework — прямой преемник AutoGen и Semantic Kernel; AutoGen теперь только поддерживается, а новым проектам Microsoft советует Agent Framework. CrewAI — «команда» агентов с ролями. Ещё есть LlamaIndex и Pydantic AI. Выбирать по экосистеме: на какой модели и в каком облаке вы работаете. Справа на слайде — что фреймворк берёт на себя: сверху ваш агент (роль и правила), в середине фреймворк (цикл, память, передача задачи, паузы на подтверждение, журнал), снизу модель и MCP-серверы из первой части урока.

### Слайд 17 (70:00–74:00) • Добавляйте сложность только тогда, когда простого перестало хватать

**На экране:** Лестница сложности: функции → MCP → фреймворк → A2A.

#### Спикер (4 мин)
> Лестница сложности. Начинаем сверху, с самого простого, и спускаемся ниже, только если упёрлись. Один чат и пара функций — хватит вызова функций. Нужно, чтобы один инструмент работал в Claude, ChatGPT и вашем боте — делаем MCP-сервер. Агент делает много шагов, должен помнить контекст, спрашивать подтверждение и вести журнал — берём фреймворк. Несколько агентов от разных компаний должны договориться между собой — протокол A2A.

### Слайд 18 (74:00–78:00) • A2A: стандарт, по которому агенты разных компаний договариваются друг с другом

**На экране:** Схема: ваш агент ↔ инструменты (MCP) и ↔ агент отеля (A2A).

#### Спикер (4 мин)
> Последний стандарт урока, для общего понимания. MCP соединяет агента с инструментами и данными. A2A, Agent2Agent, соединяет агентов между собой: ваш агент-ассистент просит агента отеля забронировать номер, и они договариваются, не зная, как устроены друг у друга внутри.
>
> A2A начинал Google, версия 1.0 вышла в марте 2026, а 17 августа 2026 протокол перешёл в тот же фонд при Linux Foundation, что и MCP. Для новичка достаточно знать, что такое слово есть и что это про общение агентов разных компаний.

### Слайд 19 (78:00–82:00) • Упражнение: какие MCP-серверы подключить и что разрешить?

**На экране:** Рабочий лист: четыре задачи × серверы, права, где человек; ответы в чат.

#### Спикер (4 мин)
> Упражнение в чат, 3 минуты. Каждый выбирает одну задачу и пишет: какие серверы нужны, какие права (только чтение или запись) и где должен подтверждать человек.
>
> Разбор. Продажи: CRM и почта, только чтение, подтверждение не нужно — это сводка. Бухгалтерия: Drive и таблицы, чтение одной папки; если агент правит таблицу — подтверждение. Поддержка: тикеты и почта; ответ клиенту и закрытие тикета — действия с последствиями, их подтверждает человек. HR: файлы с резюме — персональные данные: только одобренный компанией коннектор и только нужная папка.

### Слайд 21 (87:00–90:00) • MCP подключает инструменты, разрешения берегут данные, фреймворк — только когда шагов много

**На экране:** Четыре вывода и анонс L13.

Безопасность: читать запрос разрешения, давать минимум прав, «всегда» только для чтения. Фреймворк агентов нужен, когда шагов много, нужна память или несколько агентов.
