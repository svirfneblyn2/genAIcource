# Урок 08 • Домашнее задание: проверенный пакет анализа

**Курс:** GenAI Basics • Урок 08 «ИИ для анализа данных» • Модуль 3: ИИ-ассистенты в работе
**Файл:** `demo_assets/student_starter/northstar_sales_messy.csv` (учебные, вымышленные данные — можно загружать в любой сервис)
**Инструменты:** любой чат-ассистент с анализом файлов (ChatGPT, Claude, Gemini) или Copilot/ChatGPT/Claude в Excel, или Colab. Писать код самим не нужно.
**Сдача:** папка `verified_analysis_pack/` в вашем репозитории домашних заданий (`genai-homeworks/L08/`).

## Ситуация

Вы аналитик интернет-магазина Northstar. Руководство спрашивает:
**«Что изменилось в продажах с января по июнь и что нам проверить дальше?»**

У вас есть выгрузка на 73 строки. В ней есть ошибки — какие, найдите сами. Ваша задача — не «красивый ответ из чата», а небольшой пакет доказательств, который другой человек проверит за 5 минут.

## На занятии (в парах, 20–25 минут)

* Один ведёт чат с ИИ, второй проверяет: открывает код, сверяет числа, задаёт вопрос «откуда это?».
* На середине поменяйтесь ролями.
* Начните с промпта-профиля со слайда 6, потом используйте промпт аналитика со слайда 8 (он есть в шпаргалке `L08_00_Lecture_Cheatsheet.md`).

## Что сдать (5 файлов)

```
verified_analysis_pack/
  cleaning_log.md     # строки до/после, каждая правка: что, где, почему, как изменился итог
  analysis_brief.md   # 3–5 выводов; у каждого — метрика, период и база
  chart.png           # один график = один вывод; подписаны оси, единицы, период
  cleaned_data.csv    # или скрипт, который делает чистку
  verification.md     # минимум 3 проверки + 1 утверждение, от которого вы отказались
```

Шаблоны `analysis_brief_template.md` и `verification_template.md` лежат в `demo_assets/student_starter/`.

## Вопросы, на которые нужно ответить

1. Как менялась выручка по месяцам с января по июнь?
2. Какой канал принёс больше всего выручки за полгода? Какой рос быстрее всех? (Это разные вопросы.)
3. Для платных каналов (Search, Social): сколько выручки приходится на $1 рекламы? Подпишите, что это описание прошлого.
4. Какая проблема в данных могла бы изменить главную цифру, если бы её не заметили?
5. Чего **нельзя** сказать о бюджете на следующий месяц только по этим данным?

## Обязательно

* **Не исправляйте молча невозможные значения.** Если значение нельзя восстановить из файла — оставьте строку, пометьте её в журнале и напишите, у кого надо уточнить.
* **Минимум три проверки**, каждая — другим способом: число строк до/после; итог по месяцам = итог по каналам; одна строка, найденная глазами в исходном файле; график совпадает с таблицей.
* **Один отказ:** утверждение, которое звучит правдоподобно, но данными не подтверждается. Например: «Если удвоить бюджет Search, выручка вырастет». Объясните, какие данные нужны, чтобы это проверить (например, тест на части регионов).

## Критерии оценки (0 — нет, 1 — частично, 2 — хорошо)

| Критерий | 2 балла — это |
|---|---|
| Паспорт данных | названо, что такое одна строка, ключ, период, единицы |
| Чистка | каждая правка записана; невозможное значение не «починено», а помечено |
| Расчёт | числа можно повторить (код открыт или скрипт приложен), итоги сходятся |
| График | один график отвечает на один названный вопрос; оси и единицы подписаны |
| Проверка | 3+ независимые проверки, одна из них — ручная |
| Граница вывода | конкретный отказ + что нужно, чтобы проверить это утверждение |

Максимум — 12 баллов. Зачёт — от 8.

## Расширение (по желанию)

После проверки напарником доработайте пакет и напишите `stakeholder_note.md` (150–250 слов) для руководителя, разделив: что проверено; какие допущения сделаны; какие проблемы данных не решены; что анализировать дальше.

## Чего не делать

* Не загружайте в чат реальные данные клиентов, сотрудников или финансы компании — только учебный файл.
* Не сдавайте скриншот чата вместо пакета.
* Не пишите общих фраз вроде «ИИ трансформирует бизнес».
