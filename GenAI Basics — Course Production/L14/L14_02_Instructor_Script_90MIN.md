### Слайд 03 (07:00–12:00) • Streamlit — веб-страница на Python: ни HTML, ни JavaScript

**На экране:** Фрагмент скриншота официального чата llm-examples.streamlit.app с выносками: поле ключа, сообщения, поле ввода.

#### Спикер (5 мин)
> Это официальный пример от команды Streamlit, он открыт по адресу llm-examples.streamlit.app. Слева боковая панель с полем для ключа API, в центре сообщения чата, внизу поле ввода. Весь этот интерфейс — около двадцати пяти строк на Python, без HTML и JavaScript. Streamlit бесплатный, с открытым кодом; текущая версия 1.66 от 14 октября 2026, нужен Python 3.11 или новее.

### Слайд 04 (12:00–18:00) • Весь чат — 14 строк: показать историю, принять вопрос, спросить модель, показать ответ

**На экране:** Справочный код чата на 14 строк (с заглушкой ask_llm, запускается как есть) с выделенными session_state, chat_input, ask_llm.

#### Спикер (6 мин)
> Код, который рисует чат с прошлого слайда, в упрощённом виде. Писать его самим не нужно — его напишет агент. Но понимать четыре части стоит. Первая: session_state — память. Без неё история чата стиралась бы после каждого сообщения (почему — на следующем слайде).
>
> Вторая: цикл, который показывает всю историю сообщениями st.chat_message. Третья: st.chat_input — поле ввода; когда человек отправил вопрос, мы добавляем его в историю и показываем. Четвёртая: ask_llm — ваш вызов модели. Вверху файла это заглушка, которая просто повторяет вопрос, — так код запускается сразу; потом её заменяют вызовом API из L03: Gemini, OpenAI или локальная модель из L10. Ответ тоже кладём в историю и показываем. Запуск: streamlit run app.py — откроется страница в браузере.

### Слайд 05 (18:00–23:00) • При каждом клике Streamlit заново выполняет весь файл — поэтому нужна память

**На экране:** Схема цикла: клик → файл выполняется заново → память восстановлена → страница перерисована.

#### Спикер (5 мин)
> Главная особенность Streamlit. Обычная программа запускается один раз. Streamlit при каждом действии пользователя — клик, ввод текста — выполняет весь файл app.py заново сверху вниз и перерисовывает страницу. Это делает код простым, но всё, что было в обычных переменных, теряется.
>
> Поэтому есть session_state — память, которая переживает перезапуск, отдельная для каждого посетителя. Если студент жалуется «у меня стирается чат», почти всегда история лежит не в session_state.

### Слайд 06 (23:00–28:00) • Память, кэш и секреты — три вещи, которые нельзя путать

**На экране:** Три колонки (session_state, cache_data, secrets), код secrets.toml + app.py и .gitignore.

#### Спикер (5 мин)
> Три понятия, которые новички путают. session_state — память одного посетителя. cache_data (команда st.cache_data) — общий кэш для всех посетителей: например, файл faq.md читается один раз, а не при каждом клике. Поэтому в кэш никогда не кладут личные данные и ключи: их увидят все.
>
> secrets — ключи API. Они лежат в файле .streamlit/secrets.toml и читаются через st.secrets. Файл добавляют в .gitignore, иначе ключ уйдёт на GitHub. GitHub по умолчанию блокирует отправку найденных ключей в публичные репозитории, но надеяться на это не стоит.

### Слайд 07 (28:00–33:00) • Код пишет агент разработки, а вы ставите задачу и проверяете результат

**На экране:** Промпт для агента разработки: Streamlit-чат по faq.md с демо-режимом и секретами.

#### Спикер (5 мин)
> Как это делается на практике. Вы не пишете код руками — вы даёте агенту разработки (Codex, Antigravity, Claude Code) хорошее задание. В нём: что строим, на чём, где ключ, что делать без ключа, где хранить историю, как не утечь ключу и, главное, просьба объяснить код. Что такое агент разработки и как его выбрать — L16.

> Новое с весны 2026: у Streamlit есть официальная команда streamlit skills. Она подключает к агенту навыки — инструкции от авторов Streamlit, как правильно строить приложения. Агенты Claude Code, Codex и Cursor их понимают. Демо-режим без ключа — хорошая привычка: прототип можно показать на встрече, даже если ключа ещё нет.

### Слайд 09 (38:00–43:00) • Где показать прототип: свой компьютер, бесплатное облако Streamlit или облако компании

**На экране:** Три места публикации и предупреждение «публичная ссылка = публичные данные».

#### Спикер (5 мин)
> Три места. Свой компьютер: бесплатно; видите вы и, если вы в офисной сети, коллеги по адресу Network URL; остальным показываете через демонстрацию экрана в Teams. Streamlit Community Cloud: бесплатно, приложение публикуется из репозитория GitHub. Приложение из публичного репозитория — публичное; приватное приложение можно только одно. Засыпает через 12 часов без посетителей, первый зашедший его будит. Ключ кладут в настройки приложения, раздел Secrets.
>
> Внутри компании — Snowflake (компания, которой принадлежит Streamlit) или своё облако с доступом по ролям, это решают инженеры. Hugging Face Spaces, которые раньше были популярным бесплатным вариантом для Streamlit, больше не бесплатны для таких приложений. Главное правило: публичная ссылка — это публичные данные и ваш счёт за API.

Приложения приватные по умолчанию, ключ Gemini остаётся на сервере. Если вы им поделитесь, запросы других людей пойдут в ваши лимиты.

Lovable, Bolt и v0 делают сайт целиком по описанию; у всех есть бесплатный уровень с небольшим дневным лимитом: у Lovable и v0 это несколько запросов в день, у Bolt — лимит токенов. Streamlit выигрывает, когда нужны данные на Python, свои файлы и полный контроль над кодом.

### Слайд 14 (69:00–74:00) • Четыре правила прототипа: ключи, данные, деньги, вход

#### Спикер (5 мин)

### Слайд 15 (74:00–79:00) • Что меняется, когда прототип становится продуктом

**На экране:** Сравнение «прототип → продукт» по четырём пунктам и путь прототипа: ревью инженеров → безопасность (L15) → продукт (L16).

#### Спикер (5 мин)
> Прототип сделал своё дело: показал идею и собрал отзывы. Дальше его передают инженерам, и меняется многое. Код живёт в репозитории с ревью и тестами. Данные реальные, поэтому нужны права доступа и журнал. Ключ — не ваш личный, а служебный, с лимитами и мониторингом. И приложение должно работать у всех и круглосуточно. Внизу путь прототипа: прототип → ревью инженеров → проверка безопасности (L15) → продукт с агентами разработки (L16).
