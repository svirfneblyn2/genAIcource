Lecture 04 - Full Instructor Script

120-minute script with 90-minute compression path.

# Instructor goal

By the end of this lecture, students should be able to design a controlled image generation workflow and explain why prompt-only thinking is not enough.

# 0-8 min - Opening hook

Say: In text generation, a bad output can often be spotted by reading it. In image generation, bad output can look beautiful and still be unusable. The mug looks premium, but the logo changed. The product photo looks better, but the handle moved. The thumbnail is eye-catching, but it implies something false. Beautiful is not the same as production-ready.

Ask the room: If an AI image looks good, what could still be wrong? Collect quick answers: product changed, copyright risk, misleading content, wrong text, privacy issue, brand inconsistency, cost.

# 8-20 min - Mental model

Say: The model is not the workflow. The workflow is source assets, prompt, references, controls, generation, storage, review, and publication. If any of those are missing, you are gambling with pixels.

Show the workflow slide. Walk left to right: input assets, prompt, reference strategy, model/API call, generated candidates, review checklist, approved asset. Stress that professional workflows keep metadata: prompt, provider, model, date, input asset ID, output hash, reviewer, usage rights.

# 20-35 min - Vocabulary without design fog

Explain text-to-image, image-to-image, inpainting, outpainting, reference image, mask, variation, and acceptance criteria. Keep it practical. Use the mug example: text-to-image creates a mug scene from scratch; image-to-image starts from a mug photo; inpainting changes the background; outpainting extends the canvas; a mask protects the product; acceptance criteria decide whether it can be used.

# 35-50 min - Prompt anatomy

Say: A prompt is not a poem. It is a production brief. Good image prompts describe subject, composition, scene, style, references, constraints, and acceptance criteria. The most important line is often what must not change.

Show weak vs professional prompt. Ask students which parts control randomness: protected product reference, unchanged geometry, background-only edit, lighting direction, no text, no hands, aspect ratio, three variants, ecommerce approval criteria.

# 50-65 min - API workflow

Walk through the API lifecycle: prepare files; upload reference and mask if the provider requires it; create generation or edit request; wait or poll if asynchronous; decode or download results; save images; store metadata; run review checks; publish only after approval. Explain that some APIs return base64/image bytes, some return URLs, and some use job IDs for polling. The code changes, but the workflow stays stable.

# 65-80 min - Provider landscape

Say: We are not ranking vendors today. Rankings become stale faster than lecture slides. We compare capabilities. Ask: Does it generate? edit? accept references? support masks? preserve products? handle text? support batch jobs? provide safety controls? fit enterprise rights and governance?

Use OpenAI, Gemini/Nano Banana, and Adobe Firefly Services as examples of API families. Make clear that exact model names and limits must be checked before real delivery.

# 80-100 min - Live demo

Run the three-round demo from the demo runbook. Do not chase a perfect picture live. The teaching point is difference in control. If the model output fails, use the failure: ask which part of the workflow needs stronger constraints, reference image, mask, or human review.

# 100-114 min - Workshop

Students work in groups. Each group chooses one use case: product background replacement, YouTube thumbnail concept, event poster, app illustration, educational diagram, marketplace listing image, or character concept. They fill the Image Generation Workflow Spec: goal, inputs, prompt, references, constraints, acceptance criteria, risks, review, metadata, non-automation boundary.

# 114-120 min - Debrief and homework

Ask one group to present their spec. Push on the weakest area: what must not change? who approves? what metadata is stored? what happens if the output is beautiful but wrong? Assign homework: produce a final workflow spec plus one prompt iteration log. No real private data. No copyrighted characters. No sensitive faces.

# 90-minute compression path

• Reduce provider landscape to 8 minutes.

• Run only two demo rounds: weak prompt and controlled prompt.

• Make workshop 10 minutes instead of 14.

• Keep source/provenance discussion to one practical checklist.

# Common questions




| Question | Answer |
| --- | --- |
| Is prompting enough? | No. Prompting is one part. Production value comes from references, masks, review, metadata, and acceptance criteria. |
| Should final text-heavy graphics be generated by AI? | Usually no. Generate concepts, then use editable design or slide tools for exact labels and layout. |
| Can we upload any image? | No. Check privacy, consent, rights, and provider policy before uploading. |
| Why store prompts and metadata? | For debugging, reproducibility, cost review, safety audit, and knowing how an asset was created. |
