* **Слайд 05 (13–17 мин) • Ловушка: Красиво ≠ Пригодно (Pretty ≠ Usable):** В тексте плохой ответ видно глазами. В графике картинка может выглядеть великолепно, но быть абсолютно непригодной для бизнеса: уплыла форма кружки, изменился логотип бренда, искажены пропорции этикетки, галлюцинация лишних пальцев, юридические риски копирайта и нулевая воспроизводимость.
* **Слайд 06 (17–21 мин) • Смена модальности: Физика диффузии и латентного пространства:** Почему картинка — это не BPE-токены. Авторегрессионные LLM предсказывают следующее слово, а диффузионные модели и визуальные трансформеры (DiT) работают через латентное пространство (VAE): инжекция гауссовского шума и пошаговое удаление шума (Denoising Steps), направляемое текстовыми эмбеддингами CLIP/T5.
* **Слайд 07 (21–25 мин) • Ментальная модель: Генерация как пайплайн (C4-схема):** Модель — лишь один блок в цепочке. Инженерный пайплайн: `Исходные ассеты (фото продукта + альфа-маска)` ➔ `API Gateway (квоты, пропорции 16:9, seed)` ➔ `Inference Cluster` ➔ `Декодер Base64` ➔ `Cloud Storage (S3/GCS)` ➔ `База метаданных (промпт, хеш, seed, модель, цена)` ➔ `Human Review Gate (шлюз модерации)`.
* **Слайд 08 (25–29 мин) • 6 визуальных примитивов:** 
  1. *Text-to-Image* — генерация с нуля по текстовому брифу.
  2. *Image-to-Image* — трансформация референсного изображения.
  3. *Inpainting* — замена пикселей строго внутри маски.
  4. *Outpainting* — достраивание сцены за пределами исходного холста.
  5. *Reference Conditioning* — управление стилем, композицией или идентичностью объекта.
  6. *Negative Constraints* — жесткий запрет нежелательных артефактов.
* **Слайд 09 (29–33 мин) • Анатомия промпта: Инженерное ТЗ, а не поэма:** Промпт для API — это структурированная спецификация: Объект (Subject) ➔ Композиция и ракурс (Composition/Camera) ➔ Окружение и свет (Scene/Lighting) ➔ Стилистика (Style) ➔ Неприкосновенные атрибуты (Sacred Attributes) ➔ Критерии приемки (Acceptance Criteria). Главная строчка в ТЗ — **что категорически нельзя менять**.
* **Слайд 10 (33–37 мин) • Before / After: Слабый промпт vs Инженерный бриф:** Сравнение в лоб. Слабый: *«Сделай красивую рекламу этой кружки»* ➔ мусорный результат со сменой формы ручки. Инженерный: *«Использовать фото как защищенный референс. Сохранить геометрию керамики и ручки на 100%. Заменить только фон на светлый травертин. Ракурс на уровне глаз, 16:9, без людей, без текста. Вернуть 3 кандидата»*.
* **Слайд 11 (37–41 мин) • Сигналы референсов и мультимодальный контроль (C4-схема):** Референс — это не «вдохновение», а управляющий вектор. Разделяем: 1) *Identity Reference* (IP-Adapter — лицо, геометрия товара); 2) *Style Reference* (цветовая гамма, свет); 3) *Layout/Pose Reference* (ControlNet — глубина Depth Map, позы OpenPose, контуры Canny).
* **Слайд 12 (41–45 мин) • Механика Inpainting и маскирования (Схема):** Как устроен инпейнтинг под капотом. Бинарная альфа-маска делит изображение на 2 зоны: Черная (0) — замороженные пиксели, Белая (255) — зона зашумления и новой генерации. Размытие границ (Mask Blur/Edge Feathering) для бесшовного слияния света и теней.
* **Слайд 13 (45–48 мин) • Жизненный цикл API и сетевые пакеты:** Что летит по проводу. Запрос: Multipart form-data или JSON с `data:image/png;base64`. Ответ: прямые байты Base64 или временный URL в CDN. Синхронные вызовы vs Асинхронные очереди (Job ID + Webhook/Polling для тяжелых генераций).
* **Слайд 14 (48–50 мин) • Ландшафт провайдеров без маркетингового хайпа:** 
  - *OpenAI*: GPT-Image-2 / DALL-E (генерация и редактирование через Images API).
  - *Google*: Gemini 3.1 Flash Image / Imagen 3/4 (мультимодальное редактирование через единый контекст диалога).
  - *Adobe Firefly*: Image5 / Photoshop API v2 (корпоративные авторские права, промышленный инпейнтинг и вектор).
  - *Open Source*: FLUX.1 / SDXL (локальный деплой на RunPod/ComfyUI с абсолютным контролем весов).
